# 프로젝트 목표

- 사용자 트래픽이 순간적으로 급증하는 지정석 티켓팅 서비스 구현.
- 동시 요청에도 중복 예약 방지하고 Redis 적용 전 후 성능 비교까지 수행한다

동시성 제어. Redis, 대기열, 부하 테스트

# MVP 범위

- 포함
    - 로그인 - 사용자 식별
    - 공연 조회
    - 좌석 조회 및 5분 선점 기능
    - 모의 결제 → 그냥 무통장 입금으로
    - 예약 확정 - 조회 - 취소
    - 중복 예약 방지 기능
- 제외
    - 실제 카드 결제 API
    - 관리자 웹 화면
    - 쿠폰, 포인트
    - 추천 시스템
    - 알림 발송
    - Redis Cluster
    - Kafka
    - 좌석 배치도 그리는 UI - 일단 서버 구현에 집중한다

# 핵심 흐름

로그인 → 공연 선택 → 회차 선택 → 좌석 선택 → 5분 선점 → 결제 성공 → 예약 확정

실패 흐름

- 다른 사용자가 좌석 선점
- 선점 후 5분이 지남
- 결제 실패
- 같은 요청 여러번 전달
- 결제 직전에 좌석 선점 만료

# 정책

- 사용자당 최대 예약 좌석 2개
- 다중 좌석 중 하나 실패하면 전체 실패 처리
- 선점 유효시간 - 5분
- 예약 취소 가능 시점 - 공연 시작 1시간 전까지
- 결제 실패 시 선점 해제 방식
- 같은 요청 반복했을 때 처리 방식
- Redis/MySQL 장애 시 신규 예약 허용 여부
