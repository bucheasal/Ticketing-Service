# 프로젝트 목표

- 사용자 트래픽이 순간적으로 급증하는 지정석 티켓팅 서비스 구현.
- 동시 요청에도 중복 예약 방지하고 Redis 적용 전 후 성능 비교까지 수행한다

동시성 제어. Redis, 대기열, 부하 테스트

# MVP 범위

## 포함
  - 공연 조회
  - 회차 조회
  - 좌석 조회
  - 테스트용 사용자 식별
    - 로그인/JWT 없이 `X-User-Id` 헤더 사용
  - 좌석 5분 선점
  - 예약 확정
  - 중복 예약 방지
  - 사용자당 최대 예약 좌석 2개 제한
  - 다중 좌석 선점/확정 원자성 보장
  - Redis 적용 전후 성능 비교
  - 부하 테스트

## 제외
- 로그인/JWT 인증
- 실제 카드 결제 API
- 모의 결제 API
- 예약 취소
- 환불 정책
- 관리자 웹 화면
- 쿠폰, 포인트
- 추천 시스템
- 알림 발송
- Redis Cluster
- Kafka
- 좌석 배치도 UI

# 핵심 흐름

공연 선택 → 회차 선택 → 좌석 선택 → 5분 선점 → 예약 확정

예약 확정 API는 결제 성공을 가정한다. 별도의 결제 API와 결제 실패 흐름은 MVP에서 다루지 않는다.

실패 흐름

- 다른 사용자가 좌석 선점
- 선점 후 5분이 지남
- 같은 요청 여러번 전달
- 예약 확정 직전에 좌석 선점 만료
- 사용자당 최대 예약 좌석 수 초과
- 다중 좌석 중 일부 좌석 선점 실패

# 정책

- 사용자당 최대 예약 좌석 2개
- 다중 좌석 중 하나 실패하면 전체 실패 처리
- 선점 유효시간 - 5분
- 같은 요청 반복했을 때 처리 방식
- Redis/MySQL 장애 시 신규 예약 허용 여부
